# Internationalization and language capabilities

## UI architecture

CropPilot uses a small custom React/Zustand locale store and JSON message
catalogs. It does **not** use i18next, and no translation API is called at
runtime. Static UI messages are bundled from `frontend/i18n/messages/`.
Placeholders use `{name}` syntax; the validator checks placeholder parity.

## UI catalogs currently available

The current catalog set is 11 of the 23 canonical locale codes:

| Code | Language | Catalog |
|---|---|---|
| `en` | English | available |
| `te` | Telugu | available |
| `hi` | Hindi | available |
| `ta` | Tamil | available |
| `bn` | Bengali | available |
| `mr` | Marathi | available |
| `gu` | Gujarati | available |
| `ne` | Nepali | available |
| `pa` | Punjabi | available |
| `sa` | Sanskrit | available |
| `ur` | Urdu | available |

The canonical registry also contains Assamese (`as`), Bodo (`brx`), Dogri
(`doi`), Kannada (`kn`), Kashmiri (`ks`), Konkani (`kok`), Maithili (`mai`),
Malayalam (`ml`), Manipuri (`mni`), Odia (`or`) and Sindhi (`sd`). Their UI
catalog files are not yet shipped. The language selector lists only the
available UI catalogs; legacy/browser/backend locale codes without a catalog
resolve to English UI and English document direction. This is a known release
limitation, not a claim of 23-language UI support.

No runtime machine translation is used. Static catalogs should be reviewed
by fluent speakers before being described as publication-quality. The key
and script validator proves structure, not translation quality.

## UI versus voice

A translated UI catalog does not imply that assistant text generation, ASR or
TTS supports that language. Assistant language handling and engine capability
are separate. Consult `docs/assistant-voice.md` for configured engines and
their actual language matrices; never infer voice availability from this
catalog list.

## RTL

The canonical language registry marks RTL languages. Urdu (`ur`) is currently
the only RTL UI catalog in the shipped set. RTL direction is applied from the
effective loaded UI catalog, not from an unsupported locale request. Kashmiri
and Sindhi are registered but have no shipped UI catalogs yet.

## Catalog validation and source audits

Run from `frontend/`:

```powershell
python scripts/i18n-validate.py
python scripts/i18n-audit.py
python scripts/i18n-keys.py
```

`i18n-validate.py` checks the canonical locale files, flattened key parity,
non-empty values, placeholder parity and a native-script heuristic. It reports
missing catalog files explicitly. `i18n-audit.py` scans source for likely
hardcoded UI strings; its output is a review aid and can include false
positives. `i18n-keys.py` checks static `t("namespace.key")` references.
These checks do not establish linguistic correctness or full route coverage.
